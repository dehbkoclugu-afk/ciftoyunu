# Project instructions

- Treat `docs/product/master-implementation-plan.md` as the product contract and source of truth.
- At the start of any task-oriented session, invoke the `task-observer` skill before using tools or producing deliverables.
- When loading a skill, check `skill-observations/log.md` for OPEN observations tagged to that skill.
- Never ship draft content, mock purchase success in production, hard-coded store prices, or untranslated fallback questions.
- Keep changes within the current PR slice; do not mix dependency upgrades with feature work.
